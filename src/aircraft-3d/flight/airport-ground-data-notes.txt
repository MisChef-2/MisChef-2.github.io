AIRPORT GROUND DATA — source and integration notes

File: airport-ground-data.json
Schema: {metadata, airports: {ICAO: {icao,status,source,operationalRestrictionsStatus,features,counts}}}
features are standard GeoJSON Features; coordinates are [longitude,latitude].
properties.aeroway and properties.kind preserve the feature class. All original OSM tags are retained, including ref, name, oneway, access, width, clearance and review when present. No missing restriction is converted into permission. properties.nodeIds corresponds one-to-one to LineString coordinates. osmType/osmId/osmVersion/osmTimestamp/sourceUrl retain source identity. Source raw-file SHA256, query bounding box and OSM database snapshot are airport-level metadata.

Stand vs gate
OSM aeroway=gate normally locates passenger boarding inside the terminal. It is not an aircraft parking coordinate. OSM parking_position nodes locate the nose-wheel stop, not the aircraft model origin. OSM parking_position ways are mapped from the relevant taxiway toward the nose-wheel stop. Use the final end only when connectivity confirms it is an actual end, not an intermediate split segment; ambiguous branching/ends must remain held. A stand identifier can differ from the boarding-gate identifier. Jeju's unnamed ways must not inherit nearest gate numbers. Label verified endpoints by OSM source ID and explicitly say the stand number is unknown.

Connectivity validation
Raw node/coordinate array lengths and all geographic coordinates passed validation.
184/205 Incheon point stands and 255/261 Narita point stands lie within10m of a mapped taxiway/taxilane/stand-line endpoint. This is a proximity diagnostic, NOT proof that a gap is paved or operationally permitted. Graph routing must independently check connection, runway crossings, stand endpoint semantics and prohibit arbitrary apron/grass bridges. Original ref-less or unconnected points remain in source data, but should not become selectable routes by assumption.
Relations were not reconstructed into potentially incorrect polygons: the existing chart's apron/terminal polygons are included as contextOnly/sourceDerivative, not routing evidence. Raw relation records remain in the archived source files.

Operational scope
Map geometry is not ATC clearance, current closure information, aircraft compatibility, wingtip clearance, pavement strength, permitted pushback or a published taxi procedure. Selected topology paths must be described as geometric OSM-based illustrations. The current source set does not certify these operating restrictions.
